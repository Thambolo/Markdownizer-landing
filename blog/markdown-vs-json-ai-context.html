Markdown vs. JSON for AI Context: Readability, Structure, and Token Cost

Markdown reads like a document; JSON names fields explicitly. Choose the shape that matches the job that consumes it.

Markdown is usually easier for a person to read as notes, an explanation, or a source excerpt. JSON is useful when data needs named fields, predictable nesting, or validation by software. Each format includes syntax, and neither is guaranteed to use fewer tokens for every input. Choose based on whether the next step needs prose or structured data, then count the exact representation if a particular model's limit matters.

This is about how to provide context to an AI workflow, not about Markdownizer converting JSON files. Markdownizer converts the current webpage to Markdown; its feature inventory does not claim general JSON conversion. For measured synthetic counts, see the tokenizer method and examples.

Markdown gives prose a readable hierarchy

Headings, paragraphs, lists, and simple tables are natural when a person wants to inspect a source or explain relationships in ordinary language. A Markdown note can introduce a question, quote an excerpt, and add caveats in the same file. It can also contain plain text that does not fit neatly into a field schema.

The trade-off is that Markdown conventions are flexible. A heading may be a section title or a line that merely looks prominent. A table's column names are visible, but a complex grouping or merged cell may need an explanation. Review the representation against the source instead of assuming the syntax communicates every nuance.

JSON names values for software

JSON can make a record's shape explicit:

{
  "source_title": "Example handbook",
  "version": "2.1",
  "requirements": ["keep the unit", "mark missing values"],
  "verified": false
}

This is an illustrative record, not a real product specification. Field names can clarify what a value means, and a receiving program can validate whether the expected keys and types are present. JSON is useful when you need a stable data contract, an extraction result, or a tool call with defined arguments.

That explicitness has a cost: braces, quotes, commas, and repeated key names appear in the submitted text. Compact arrays may reduce repetition, but they can make positional meaning less obvious unless the schema is also supplied. Invalid escaping or a missing comma can break parsing even when a human can guess the intent.

Token cost depends on the exact representation

Tokenizers do not charge a fixed amount per Markdown marker or JSON key. A repeated key may tokenize efficiently; punctuation can split differently; long field names add characters. The balance depends on the exact values and tokenizer. Avoid saying JSON is always smaller, or Markdown always cheaper, based on the number of visible lines.

For a fair test, represent the same facts in both forms, including the same source labels, dates, units, and caveats. Count them with the model-family selector you expect to use. The public OpenAI Tokenizer can help with inputs for its displayed model groups. The example-count article reports a small table sample, not a universal format ranking.

Pick a format by the task

  • Choose Markdown for a readable article excerpt, explanation, review notes, or prompt where section flow matters.
  • Choose JSON for a machine-consumed record, an explicitly typed field set, or an integration that requires a schema.
  • Choose a Markdown table, CSV, or JSON array for tabular data only after checking how the receiving tool interprets the relationships.
  • Keep source provenance in either format so a value can be traced to its title, URL, date, or version.

If an AI tool asks for JSON output, that requirement is about the output format and may be separate from the format of the source context. State which is which. A clear instruction does not by itself validate an answer; parse or check the result when downstream software depends on it.

Keep the source and sharing boundary clear

When using webpage text, confirm that you may share it and trim unrelated details.
