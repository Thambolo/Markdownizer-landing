Markdown basics

How do I open and edit a .md file?

A Markdown file is plain text. Open it in a text editor, keep its .md extension, and preview the rendered result when available.

To open and edit a .md file, use a plain-text editor or an app with Markdown support. If your computer opens it in an unexpected program, use the file manager's "Open with" option to select an editor. Edit the text, save the file, and preview it in the app where you plan to use it. You do not need a special Markdown editor just to read the source.

Choose the view you need

A text editor shows the literal source, including markers such as #, -, and backticks. A Markdown preview renders many of those markers as headings, lists, links, and code. Use the source view to make precise edits and the preview to catch layout or rendering differences.

Many code editors include a Markdown preview. For example, the official Visual Studio Code Markdown guide documents its built-in preview and editor shortcuts. These details apply to VS Code; other editors may use different menus and support different Markdown extensions.

Make a first edit

  1. Save a copy of the original file before changing a document you may need to restore.
  2. Open the file in a plain-text editor and check that the content looks like text, not unreadable symbols.
  3. Make one small change, such as editing a heading or correcting a sentence.
  4. Save with the .md extension. Avoid accidentally appending .txt if the editor asks for a filename.
  5. Open the preview and check headings, list nesting, links, tables, and code blocks.

Simple Markdown example:

# Meeting notes

## Decisions
- Keep the source link.
- Confirm the next review date.

See the [project guide](https://example.org/guide).

The URL is a placeholder. In a real note, use the source destination you intend and verify that it still opens.

Know where Markdown differences can appear

Markdown has dialects and app-specific extensions. A table, checkbox, or embedded diagram may render in one application and appear as literal characters in another. If you send the file to someone else, ask what their app supports or keep a plain-text fallback. CommonMark's tutorial covers core syntax, while the specification documents its defined behavior.

Check links and content before sharing

Preview does not prove that every link is valid or that external content is safe. Click important links, check image paths, and inspect any code or commands before using them. A local relative link may work on your computer but fail after you move the file unless the linked file moves with it.

If the file contains a webpage conversion, keep the page title and original URL, review the text and link destinations, and remove unrelated or sensitive details before sending it. Markdownizer can download a webpage as a .md file, but editing and previewing happen in a separate app. See how to save a webpage as a Markdown note.
