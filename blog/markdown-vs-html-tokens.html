Formats and token cost

Markdown vs. HTML: How Many Tokens Does Webpage Markup Add?

HTML often carries more syntax than a Markdown rendering of the same content, but the difference depends on the exact source and tokenizer.

HTML can add token overhead because it includes element names, delimiters, closing tags, and sometimes attributes such as classes, styles, or link destinations. Markdown usually represents common structure with fewer kinds of markers. But there is no fixed conversion ratio: tokenizers split text differently, and the source can contain very different amounts of markup. A meaningful comparison must hold the readable content constant and count both versions with the same model-family tokenizer.

Token count is also only one consideration. HTML may be the appropriate input when a system needs source markup, attributes, or a DOM transformation. Markdown may be easier to review when the task needs headings, lists, links, or code as prompt context. Neither representation guarantees a more accurate answer. See the reproducible token-count examples for a small, explicitly limited test.

Where HTML's extra text comes from

A short paragraph can be wrapped in an opening and closing tag. A link includes an anchor tag and an href value. A real page may repeat long class names on many elements, include tracking or accessibility attributes, and contain scripts or navigation unrelated to the question. The tokenizer sees the characters that are actually submitted; it does not know that some are invisible styling or boilerplate unless a preprocessing step removes them.

Not all HTML attributes are waste. A link destination, image alternative text, language marker, or table relationship may matter. Removing attributes mechanically can discard useful context or change meaning. First decide what information the task needs, then choose a representation that preserves it.

Why token counts do not map to tags

It is tempting to assume that one HTML tag costs one token or that Markdown always uses a particular fraction of the tokens. Neither is a safe rule. Common strings can be represented as a single token or several, depending on the vocabulary and neighboring characters. A verbose URL, an unusual class name, indentation, and repeated phrases can change the count. Different model families may use different tokenization.

Compare the exact prompts you expect to use. Keep the text, link destinations, and relevant facts the same, change only the markup, and record the tokenizer selector. If you also remove menus or repeated footers, measure that as a separate change rather than crediting the format conversion for the reduction.

Choose by the consumer, not by a slogan

  • Use HTML when a parser, browser automation job, or extraction pipeline needs element attributes or source-level structure.
  • Use Markdown when a person or AI chat needs a readable document with common semantic boundaries.
  • Use plain text when formatting adds no useful distinction and the relevant context is already clear.
  • Remove irrelevant page content when it does not support the task, while retaining definitions, qualifications, units, and source details.

Changing a web page into Markdown is not the same as sending a whole HTML document to a model. A browser converter may extract a subset before formatting it, while another service may parse the page differently. To isolate these effects, compare like with like: first hold the content constant to examine format, then test a separate, carefully reviewed scope reduction.

What this means for Markdownizer

Markdownizer converts the active HTTP or HTTPS webpage into Markdown that you can copy or download. It does not accept arbitrary HTML files as a general-purpose document-conversion feature. Read the feature guide for supported webpage structure and limitations, and check the output because page-specific markup can affect what is extracted.

When content is removed or simplified, review whether the remaining headings, tables, links, and code still express the relationships your question relies on. For simple tables, see the table review checklist. For token measurements rather than rules of thumb, use the OpenAI Tokenizer and document the selected model-family option and exact input.
