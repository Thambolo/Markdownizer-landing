Token measurement

How to Measure Your Prompt's Token Count with OpenAI's Tokenizer

Use a public sample, record the model-family option and exact text, and treat the result as a measurement of that input only.

To measure a prompt's token count, paste the exact text into a tokenizer for the model you plan to use, record the selector and count shown, and repeat with one controlled change at a time. A tokenizer result describes that input under that tool's current selection; it is not a universal word-to-token ratio or a guarantee about the destination app's total usage.

The examples below were entered in the public OpenAI Tokenizer on November 9, 2026. The selected interface label was GPT-5.x & O1/3. The page offered model-family groups and did not display an encoding name in the visible interface, so this report does not infer one. Samples are invented and contain no private webpage text or secrets.

Hold the content constant when comparing formats

First, compare the following Markdown and plain-text variants. The readable words are the same; the plain-text version removes the heading and list markers. Both include line breaks.

# Field Notes

## Before You Share
Review the source URL and remove details you do not need.

- Keep the page title.
- Check every table heading.
- Mark facts the source does not state.
Field Notes

Before You Share
Review the source URL and remove details you do not need.

Keep the page title.
Check every table heading.
Mark facts the source does not state.

For this exact sample, the tokenizer showed 42 tokens and 185 characters for Markdown, and 37 tokens and 174 characters for plain text. This is a five-token difference in one short example. It does not establish a typical overhead or say whether either version would produce a better answer.

For this exact pair, Markdown showed 53 tokens and 228 characters; HTML showed 88 tokens and 291 characters. The test does not represent every page, because real HTML can contain different tags, attributes, scripts, or omitted content. It also does not isolate extraction behavior from formatting in a real converter.

For these exact strings, the tokenizer showed 43 tokens and 136 characters for the Markdown table, 28 tokens and 79 characters for CSV, and 38 tokens and 126 characters for JSON. CSV was the shortest of this tiny sample; it relies on the reader knowing that each position follows the header row. A different table, quoting pattern, or schema could change the relative counts.

Reproduce the test carefully

  1. Open the linked OpenAI Tokenizer and note the model-family selector exactly as displayed.
  2. Paste one complete sample, including its newlines, spaces, punctuation, and URLs.
  3. Record the count and character total. Do not silently edit the input between runs.
  4. For a format comparison, keep the readable content and source details equivalent.
  5. For a scope comparison, keep the format fixed and remove only a named section.
  6. Report the date, tool, selector, exact input, and what the test does not cover.

Do not mix a format change with a scope reduction. If you remove navigation and convert the remaining article from HTML to Markdown at the same time, you cannot attribute the count difference to either change by itself.

What these counts do not measure

These text samples do not estimate the cost of uploading a PDF, DOCX, screenshot, or image. A destination may parse files, OCR a scan, or process visual input through model- and tool-specific mechanisms. Counting extracted text is not the same as counting the full ingestion or billing path. Check the destination's own documentation for files and image input.

The OpenAI tool is a tokenizer, not an independent evaluation of Markdownizer or a quality benchmark. The counts do not show that Markdown saves tokens on typical pages, improves AI accuracy, or beats another converter. For context selection, see what actually saves tokens and how much source material to include.

Use counts as a narrow planning aid

For your own prompt, include the instruction, source, and relevant context that the destination will actually receive. Markdownizer's popup character count is not a model token count. Measure with the intended tool or official model tokenizer when available, then verify that any trimming preserves necessary definitions, units, caveats, and source identity.
