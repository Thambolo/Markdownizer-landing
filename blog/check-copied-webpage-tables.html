Formatting and review

Why webpage tables break when copied, and how to check them

A table is more than numbers in sequence: each value needs to stay attached to the right row, column, unit, and note.

Webpage tables can become hard to use after copying when the relationship between a value and its header is lost. Some clipboard paths preserve table formatting; others flatten cells into text or change spacing. Conversion to Markdown can make row and column boundaries explicit, but complex tables still need a visual check against the source.

Markdownizer converts supported HTML tables into Markdown tables. Nested tables can be simplified, and missing headers may be inferred; merged cells and complex visual groupings need particular attention. These behaviors are described in the current feature guide, and they are reasons to review, not assume, the result.

Why a table needs its structure

Consider a schedule with a task, owner, due date, and status. If the row boundaries disappear, "Friday" may be mistaken for a date belonging to the wrong task. A metric table can be even more sensitive: "12" without a unit might mean hours, percent, users, or something else. A footnote may qualify only one cell, not the whole table.

Visual layout can also carry meaning that a plain grid does not express. A spanning header may group several columns; a blank cell may mean "same as above," "not applicable," or "not reported." A Markdown table has a simple rectangular structure and cannot faithfully represent every merged or nested arrangement.

Check the conversion against the source

  1. Start with the complete table. Confirm the title or caption, column headers, units, row labels, notes, and source date are visible before converting.
  2. Convert the relevant page and locate the table in the result. If Smart selection excludes it, consider full-page capture for that conversion; full-page capture still depends on content loaded in the page body.
  3. Compare a few rows from top to bottom. Verify each value sits under its original header and remains attached to the right row label.
  4. Check the edges. The first and last columns or rows are easy to overlook when a table is wide or long.
  5. Reattach notes explicitly. If an asterisk, unit, period, or qualification is separated from its cell, add a clear note in your working copy.
  6. Stop if meaning is ambiguous. Return to the source or manually transcribe the critical portion rather than asking an AI to guess.

Use a small example to test row associations

The following is an illustrative table, not real product or research data:

| Item | Measure | Unit | Period |
| --- | ---: | --- | --- |
| Example A | 12 | hours | per week |
| Example B | 8 | hours | per week |

Before using a table like this, ask: Is the measure attached to the intended item? Is "hours" the unit for both rows? Does "per week" apply to both entries? Is there a hidden note that changes the interpretation? In a real source, compare the values directly with the webpage rather than treating this format as proof.

Tell the AI what to preserve

If the table is suitable to share, label its source and ask a bounded question. For example: "Using only the table below, compare the values by row. Keep the unit and reporting period with every number. Mark missing or ambiguous cells; do not infer them." This instruction can make your expectations clear, but it cannot guarantee that a model will parse or calculate correctly.

For product pages, also keep currency, billing period, product variant, and checked date attached to a price. See how to compare product pages with AI. For API documentation, a version or parameter table may affect code behavior; read the coding workflow guide.

When a text table is the wrong representation

If the table's meaning depends on color, spatial grouping, a complex header hierarchy, or a chart-like layout, use an authorized accessible data export or manually prepare a clear representation. A screenshot may preserve visual grouping for a tool that can inspect images, but image understanding depends on the destination and does not replace checking important numbers against the source.

Markdown is useful when a simple grid can express the relationships. It is not a lossless copy of every table design. For a broader comparison of text and visual context, see Markdown vs. screenshots for AI context.
